Collaborative Forest Stewardship

Species-level forest inventories are scarce, costly, and often out of reach for the communities that depend on these forests most. Our pipeline changes that — processing high-resolution crown imagery through advanced computer vision to segment individual tree crowns, then AI-driven species classification, exporting a georeferenced map as KMZ polygons any community, school, or conservation body can open in standard GIS tools.

The register belongs to the stewards who verify and extend it — municipalities validate land claims, students study biodiversity, conservationists plan restoration, all from one shared, open dataset. Forest intelligence built from the ground up: a collaborative step toward social-ecological resilience.

Guide & FAQ

New to this? Read the Parameter Guide →

New here? Start reading — or hover the i on each step.

What is this tool?
An end-to-end pipeline that maps tree species from drone orthomosaics. It detects individual crowns, groups them by visual similarity, lets you assign species names, and exports a geospatial map you can open in Google Earth or GIS tools.
What do I need to get started?
  • A drone survey exported as a GeoTIFF (.tif) — RGB or multispectral
  • A signed-in account (Google sign-in on the landing page)
  • Rough knowledge of the tree species present in your area
No programming skills required.
What happens step by step?
1 → Create project: reserves a folder for all your files.
2 → Upload: your orthomosaic is stored on the server.
3 → Analyze: AI detects crowns and clusters them by appearance.
4 → Label: you assign species names to each cluster.
5 → Finalize: exports the labelled species map.
How long does analysis take?
Depends on image size and server hardware:
  • Small area (~500 crowns) — 5–15 min
  • Large survey (10,000+ crowns) — 1–2 hrs
The pipeline runs in the background — progress updates on each step as it runs.
What is "k" and how do I pick it?
k is how many groups (clusters) the crowns are split into — ideally one group per species. After Step 3 the app fills Chosen k with a recommended value and the label table appears automatically. To sanity-check it, open Browse output files and look at:
  • t-SNE plots — well-separated blobs = good k
  • Cluster sample images — do crowns in each cluster look like the same species?
Pick the smallest k where each cluster clearly maps to one species type. Change Chosen k and the table updates instantly.
What do the analysis parameters mean?
Defaults suit most surveys. Step 3 groups them by the stage they affect:
  • Detection — Detectree2 tile_size detection tile edge (m); smaller = finer but slower · buffer tile overlap (m) so edge crowns aren't cut · iou_threshold merge overlapping boxes above this (0–1) · conf_threshold keep detections above this confidence (0–1)
  • Crown embedding — DINOv2 the feature extractor turns each crown into a vector. It also fixes the crop size, so there is nothing else to set here.
  • Clustering — PCA + KMeans pca_components feature dims before clustering; lower = faster · k_list candidate cluster counts tried; one is recommended
Each field also shows this hint inline in Step 3. The coordinate system is read from the GeoTIFF, and batch size is fixed by the server's GPU memory — neither is yours to set.
How do I use FileBrowser?
Click any Browse output files → link after project creation, analyze, or finalize. It opens a shared folder — no login needed.

Key folders inside your project:
  • step1_output/ — detected crown polygons
  • step2_output/ — DINOv2 feature files
  • step3_output/ — cluster plots & sample images
  • step4_output/ — final KMZ & CSV exports
What outputs do I get after Finalize?
  • species_map.kmz — open in Google Earth Pro; each crown is coloured by species
  • species_map.csv — per-crown coordinates, assigned species & cluster ID
  • Distribution summary — crown count per species shown on screen
Download links appear directly in Step 5 after completion.
What is a KMZ file?
A KMZ is a compressed map file readable by Google Earth Pro and most GIS tools (QGIS, ArcGIS). It displays each detected crown as a polygon coloured by species — useful for field validation, reporting, and sharing with stakeholders.
Can I re-run the analysis?
Yes. After any analysis, change the parameters (different k_list, model, thresholds) and click Run analysis again. Each run is numbered (Run 1, Run 2…). The orthomosaic is shared across runs but labels and parameters are independent per run.
What if something goes wrong?
The error message shows inline on the step that failed. Common issues:
  • Upload failed — file too large or wrong format (must be .tif)
  • Analysis failed — a pipeline error; the run's log (in your project's logs/ folder) has the details
You can retry any step without starting over.

    What happens inside, in six steps

    1. Your survey photo is one large image/TIFF
    2. It is cut into small squares called tiles, which overlap slightly.
    3. The model looks at each tile and draws an outline around every tree it recognises.
    4. Outlines from neighbouring tiles are stitched together and duplicates are merged.
    5. Each tree outline is converted into a list of numbers describing its colour and texture.
    6. Trees with similar numbers are grouped together. Those groups are your candidate species.

    The settings you can change affect steps 2, 3, 4 and 6. Everything else is fixed.

    How big does a tree look to the model?

    This one idea explains three of the settings at once, so it is worth two minutes.

    Whatever patch of ground you ask for in a tile, it is resized to a fixed picture size before the model looks at it. Think of a passport photo booth: the print is always the same size, so standing further back to fit more in only makes your face smaller in the print.

    So asking for a bigger tile does not give the model a bigger picture. It gives the same picture with everything in it smaller — and trees that get too small are simply not found.

    The sum is pixels per metre = picture size ÷ (tile size + 2 × buffer). Notice that your camera's resolution does not appear in it — a sharper survey does not make trees look bigger to the model. Only these three numbers do.
